# Fuzzy Ergonomic Risk Index (FERI) — Ergonomic Assembly Line Balancing Toolkit

A reproducible pipeline for fuzzy, AHP-weighted ergonomic assembly line balancing (Ergo-ALB): fuzzify task time and ergonomic measurements as triangular fuzzy numbers (TFNs), aggregate them into a composite Fuzzy Ergonomic Risk Index (FERI) using AHP-derived expert weights, propagate the uncertainty into an exact MILP through an α-cut parametric analysis, and solve with IBM CPLEX.

The key methodological idea: fuzzy uncertainty is **propagated into the optimization** via α-cuts rather than discarded through defuzzification before the solver ever sees the data.

---

## Data note

`example_dataset.xlsx` contains real industrial measurements (task times, energy expenditure, REBA, and Borg CR-10 scores) from a 92-task assembly line, with task names replaced by generic labels (`Task 1`, `Task 2`, ...) for confidentiality. The precedence structure and all numeric values are unmodified — only the task descriptions are anonymized. Station numbers are preserved and are not linked to any identifiable process.

If you don't have your own data yet, generate a synthetic dataset instead:

```bash
python create_example_dataset.py
```

---

## Overview

The pipeline has four steps:

1. **AHP weight elicitation** from an expert questionnaire (`ahp_weights.py`)
2. **Fuzzy FERI computation** — fuzzification, normalization, AHP-weighted aggregation (`fuzzy_eri.py`)
3. **MILP data generation** — α-cut parametric analysis produces one `.dat` file per (weight pair, α-level, scenario) combination (`milp_dat_generator_v2.py`)
4. **Exact optimization** — solved with IBM CPLEX OPL (`assembly_line_new_model.mod.txt`)

An optional **interactive dashboard** (`dashboard/feri_dashboard_public.html`) visualizes FERI results — open it directly in a browser, no server required.

## Step-by-Step Guide

### Step 0 — Prepare your input data

Edit `example_dataset.xlsx` with your own data, or start from the synthetic generator. The file needs two sheets:

**Sheet `Tasks`** (title note on row 1, headers on row 2):

| Task ID | Station | Task Name | Time (s) | Energy (kcal) | REBA | Borg |
|---------|---------|-----------|----------|---------------|------|------|
| 1       | 1       | Bolt assembly | 45   | 0.12          | 4    | 3    |

- **Task ID**: integer identifier
- **Station**: physical workstation number (used for precedence-diagram coloring and workstation-contiguity constraints)
- **Time (s)**: observed task duration
- **Energy (kcal)**: metabolic cost per task execution
- **REBA**: whole-body postural risk score (1–15)
- **Borg**: perceived exertion, CR-10 scale (0–10)

**Sheet `Precedence`** (title note on row 1, headers on row 2):

| Predecessor ID | Successor ID |
|-----------------|---------------|
| 1                | 3             |

### Step 1 — AHP weight elicitation

**Script:** `ahp_weights.py`

Reads pairwise comparisons for the three ergonomic criteria (Energy, REBA, Borg) from `experts_answer.xlsx` (one row per expert; not included in this repo — supply your own, real anonymized expert-survey data shouldn't be committed either). Builds a 3×3 comparison matrix per expert, screens for logical consistency and a consistency ratio ≤ 0.10, and aggregates the retained matrices via element-wise geometric mean.

```bash
python ahp_weights.py
```

If `experts_answer.xlsx` is missing or every expert is inconsistent, `fuzzy_eri.py` automatically falls back to equal-ish default weights (`energy=0.35, reba=0.35, borg=0.30`) — the pipeline still runs end to end without it.

---

### Step 2 — Fuzzy FERI computation

**Script:** `fuzzy_eri.py`

1. **Fuzzification** — each crisp measurement becomes a TFN `(l, m, u)`:
   - Time, Energy: `l = (1-δ)m`, `u = (1+δ)m`, δ = 5%
   - REBA, Borg: `l = max(0, m-1)`, `u = m+1`
2. **Normalization** — each indicator divided by the dataset-wide maximum upper bound, mapping all values to `[0, 1]`.
3. **Weighted aggregation**: `FERI = w_E · Energy_norm + w_R · REBA_norm + w_B · Borg_norm`, computed bound-wise for `l`, `m`, `u`.
4. **Export** — `FERI_results.xlsx` (per-task TFN bounds `ERI_l/ERI_m/ERI_u`, a crisp/modal value, and a qualitative risk label) and `FERI_charts.png`.

```bash
python fuzzy_eri.py
```

Configuration (top of the file):

```python
SPREAD = {
    "time":   0.05,
    "energy": 0.05,
    "reba":   1.0,
    "borg":   1.0,
}
```

> **Known limitation**: the REBA/Borg lower bound is floored at 0 rather than at each scale's true minimum (1 for REBA), and the upper bound isn't capped at each scale's true maximum (15 for REBA, 10 for Borg). In practice this mainly affects tasks with a modal REBA score of 1. A stricter implementation would use `l = max(l_min, m-1)`, `u = min(u_max, m+1)` with the real scale bounds.

---

### Step 3 — MILP data generation (α-cut parametric analysis)

**Script:** `milp_dat_generator_v2.py`

Reads `FERI_results.xlsx` and generates one `.dat` file per combination of objective weight pair, α-level, and scenario.

For a TFN `(l, m, u)`, the α-cut at confidence level α is:

```
[l_α, u_α] = [l + α·(m − l),  u − α·(u − m)]
```

| α   | Meaning |
|-----|---------|
| 0.0 | Full uncertainty — widest interval `[l, u]` |
| 0.5 | Intermediate confidence |
| 1.0 | Full confidence — collapses to the midpoint `m` |

For each α < 1, two instances are generated (optimistic = lower bound, pessimistic = upper bound); α = 1 yields a single midpoint instance.

```bash
python milp_dat_generator_v2.py
```

**Output**, for each `(w_time, w_eri)` pair in `WEIGHT_PAIRS`:

```
assembly_line.dat                                    ← base file (α=1 midpoint)
assembly_line_wt<TTT>_we<EEE>_cut00_optimistic.dat    ← α=0, best case
assembly_line_wt<TTT>_we<EEE>_cut00_pessimistic.dat   ← α=0, worst case
assembly_line_wt<TTT>_we<EEE>_cut05_optimistic.dat    ← α=0.5, best case
assembly_line_wt<TTT>_we<EEE>_cut05_pessimistic.dat   ← α=0.5, worst case
assembly_line_wt<TTT>_we<EEE>_cut10.dat               ← α=1, midpoint
precedence_diagram.png
```

With the default 5 weight pairs × 3 α-levels (2 scenarios each except α=1), that's 25 `.dat` files.

Configuration (top of the file):

```python
N_STATIONS    = 10     # upper bound on number of operator stations
CYCLE_TIME_UB = 120.0  # takt time in seconds
ERGO_LIMIT    = 30.0   # max ergonomic load (ERI × s) per station
WEIGHT_PAIRS  = [(1.00,0.00),(0.75,0.25),(0.50,0.50),(0.25,0.75),(0.00,1.00)]
ALPHA_CUTS    = [0.0, 0.5, 1.0]
TIME_LIMIT    = 285     # CPLEX solver time limit, seconds
CT_MARGIN     = 1.2     # CT_max  = (sum(TN_m)/N_STATIONS) × CT_MARGIN
ERI_MARGIN    = 1.2     # ERI_max = (sum(ERI)/N_STATIONS) × ERI_MARGIN
```

### Step 4 — Exact optimization with IBM CPLEX OPL

**Model file:** `assembly_line_new_model.mod.txt`

Rename (or copy) it to `.mod` before adding it to your OPL project:

```bash
cp assembly_line_new_model.mod.txt assembly_line.mod
```

#### Two objective functions

Activate one by uncommenting its `minimize` line in the `.mod` file:

| Objective | Formula | Description |
|-----------|---------|-------------|
| **OBJ-1 MinMax** | `w_time·cycleTime + w_eri·maxEriLoad` | Minimizes the weighted peak load across operators |
| **OBJ-2 Dual SI** | `w_time·SI²_time + w_eri·SI²_eri` | Minimizes workload imbalance in both dimensions simultaneously |

#### Running in CPLEX OPL Studio

1. Open IBM ILOG CPLEX Optimization Studio
2. **File → New → OPL Project**
3. Add the model: right-click the project → **Add Model File** → `assembly_line.mod`
4. Add a run configuration, pointing it at one of the `.dat` files from Step 3
5. Run

To recover the full fuzzy optimal solution, run the model once per `.dat` file and record the objective values — the resulting `[Z_low(α), Z_high(α)]` intervals across α-levels are the α-cuts of the fuzzy optimal objective, i.e. its membership function.

#### Key constraints

| Constraint | Role |
|------------|------|
| Assign once | Each task assigned to exactly one operator |
| Peak loads | `CT`/`EL` = max time/ERI load across operators |
| Precedence | Predecessor assigned to an operator with lower-or-equal index |
| Workstation contiguity | All operators active at a workstation finish before the next workstation starts, regardless of precedence |

## Interpreting Results

CPLEX console output includes, per run: operator assignments (tasks per operator, grouped by workstation), station time/ERI loads, utilization %, **line efficiency** (`total task time / (n_stations × cycleTime) × 100%`), and the Smoothness Index (SI) for both dimensions.

To compare results across all 25 runs at once:

1. Copy the full console output for every run into a single text/RTF file (each block headed by its run name, e.g. `assembly_line_wt000_we100_cut00_optimistic`).
2. Run:
   ```bash
   python analyze_cplex.py path/to/combined_output.rtf
   ```
   This produces `cplex_results.xlsx` (tabulated results) and charts in `cplex_analysis/` (membership functions, weight sensitivity, Pareto scatter, heatmaps).

## Adjusting the Model

| Parameter | Where | Effect |
|-----------|-------|--------|
| `N_STATIONS` | `milp_dat_generator_v2.py` | Maximum number of operators available to the optimizer |
| `WEIGHT_PAIRS` | `milp_dat_generator_v2.py` | `(w_time, w_eri)` pairs for the sensitivity sweep |
| `CT_MARGIN` / `ERI_MARGIN` | `milp_dat_generator_v2.py` | Slack above the ideal balanced load (used for OBJ-2 caps) |
| `ALPHA_CUTS` | `milp_dat_generator_v2.py` | α-levels to solve (add more for finer resolution) |
| `SPREAD` | `fuzzy_eri.py` | Uncertainty spread per indicator |
| Active objective | `assembly_line.mod` | Uncomment OBJ-1 or OBJ-2 `minimize` line |
